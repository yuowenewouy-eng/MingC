# MIngC · 提示词编译器

MIngC 是一个**只输出提示词**的 DSH Agent 预设：把用户尚未成形的想法——代码要求、界面与视觉风格修改、产品规则、流程改造、文生图/图生图提示词等——编译成**精确、可验证、可直接粘贴**的提示词与需求规格。它不执行、不生成、不修改任何东西。

它不实现代码，只产出规格。它的核心是四层行为：

1. **方向锁定**：先提取用户的目标、范围、非目标、硬约束、风格方向与优先级，提示词严格保持这些大方向。
2. **细节补全**：在方向之内，用网上资料或已知最佳实践自动补全错误处理、边界、测试、设计令牌、可访问性、命名等可执行细节，并在“自动补全的细节”中列出依据。
3. **建议闸门**：如果 MIngC 认为有更好的做法，且会改变范围、成本、依赖、架构、用户可见行为、审美方向或优先级，它**不会**写进提示词，只会放在“可选优化建议”中，等你确认后再迭代输出新版本。
4. **逻辑自检**：交付前检查提示词内部是否有方向/空间/动作/风格矛盾，并在提示词里要求执行者做“执行后自检”；发现不一致时重做或标注，不能用解释替代修正。

## 从 GitHub 安装

**最快方式（推荐）**：插件 → **添加插件** → **安装第三方插件** → 粘贴仓库地址：

```text
https://github.com/yuowenewouy-eng/MingC
```

安装完成后 bundle 默认启用；如果提示需要重启，或新任务里看不到 MIngC，重启 DSH。更新时在插件页卸载再安装（GitHub 安装会锁定到安装时的 commit）。

也可以克隆后安装本地目录：

```bash
git clone https://github.com/yuowenewouy-eng/MingC.git
```

把克隆目录的**绝对路径**粘贴到插件页安装；或下载仓库 ZIP 解压后安装该目录的绝对路径。

> 前置：DSH 0.2.1-rc.3+。GitHub 地址安装需要本机有 Git（pnpm 通过 git 拉取）；没有 Git 时用 ZIP / 本地目录方式。本地安装是链接引用：不要移动或删除目录，移动后需要从新路径重装。

## 安装

1. 打开左侧栏的 **插件** 页面。
2. 点击 **添加插件** → **安装第三方插件**。
3. 在输入框中粘贴本目录的绝对路径（示例）：

   ```text
   D:\MIngC
   ```

4. 点击安装。安装完成后 bundle 默认启用；通常会重组成新配置，新建任务即可在预设选择器里看到 **MIngC**。如果插件页明确提示需要重启，或新任务里仍然看不到 MIngC，再重启 DSH。

> 安装对话框接受 npm 包名、Git 仓库和**本地目录绝对路径**；路径或包结构不对时 Host 会返回明确原因（`not-a-package` / `not-a-bundle` / `already-installed`），不会静默失败。
>
> **CLI 备选（仅在插件页不可用时）**：先**完全退出 DSH（含托盘）**，再使用 DSH 安装目录自带的命令行（不要用 PATH 上其它来源的 `dsh`）：
>
> ```powershell
> & 'D:\deepseek harness\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop add 'D:\MIngC'
> ```
>
> 该命令会更新 profile 清单并把 bundle 追加到 `dsh.profile.bundles`，成功后重新打开 DSH。注意：`dsh --profile desktop`（启动 desktop profile 或 `--dump-config`）永远会被拒绝；只有上面这种 `plugin` 子命令、由安装目录自带的 `dsh.cmd` 执行时才受支持。其它来源的 `dsh` 会报 `profile "desktop" is managed exclusively by the Electron application`。
>
> 本地目录安装是链接引用。**不要移动或删除 `MIngC` 目录**；如果移动了，需要从新路径重新安装。修改 `cordis.patch.yml` 后不需要重装，重启 DSH（或触发配置重载）即可；同一路径重复安装会提示已安装，需先卸载再装。改完后要**新建任务**才会使用新的预设定义。

## 选择与首次使用

- **新建任务**，在预设选择器中选择 **MIngC**。
- 如果希望以后默认使用它：设置 → 通用 → **Agent 预设** → 选中 MIngC → **设为新任务默认**。
- 已经存在的会话不会切换预设，必须新建任务。
- 第一次使用建议先试：`把“设置页改得更现代、更干净”编译成设计提示词`。

### 响应速度

- **推理强度是最大因素**：`deepseek-flash` 常见档位是 **low / high**（部分界面另有 off / max）。不赶时间用 high（默认、质量优先）；追求速度选 **low**；max 最慢。
- 0.1.2 起，MIngC 每次回答最多做 **1 轮**网页检索、最多 **3 个 URL**，并限制输出篇幅；已有依据就停止检索，不再为同一主题分批抓取。
- 如果仍然偏慢：把输入缩小（只贴必要的代码片段/需求），或明确说“直接写、不要问”，减少澄清与多轮研究。

## 示例

**方向明确、细节缺失：自动补全**

> 用户：把设置页改得更现代、更干净。品牌色是 #0A84FF，要求深色模式。

MIngC 会保持“深色、克制、品牌蓝”的方向，自动补全间距体系、字号/行高、圆角、组件状态、对比度与验收判据，并在“自动补全的细节”中列出依据；不会擅自把页面改成浅色或换品牌色。

**有更好的想法：只提建议，不写进提示词**

> 用户：把登录 token 存在 localStorage 里。

MIngC 会按用户方向生成提示词，同时在“可选优化建议”中说明 localStorage 的 XSS 风险，并建议 HttpOnly Cookie 方案；在你确认之前，提示词里仍然只写 localStorage。确认后，MIngC 输出 v2，并附变更记录。

**迭代**

> 用户：采纳第 2 条建议，第 1 条不要。

MIngC 只整合第 2 条，输出更新后的完整提示词 + 变更记录，并保留未采纳项。

## 输出结构

```text
### 方向契约（锁定）
目标 / 范围 / 非目标 / 硬约束 / 成功标准 / 风格方向

### 关键假设
假设 / 依据 / 若不成立的影响

### 自动补全的细节
编号 | 补全内容 | 依据 | 影响

### 待确认
仅列会改变提示词内容的问题；每条给默认值；最多 5 条
未回答的待确认项不写入提示词，只在代码块外用【待确认 #n】占位

### 可直接粘贴的提示词
（只含方向契约与已补全细节；不含未确认建议；内含执行后自检条款）

### 逻辑自检
检查项 / 结果（通过 / 已修正 / 需确认）/ 修正或依据

### 验收清单

### 可选优化建议（未写入提示词）
编号 / 建议 / 理由 / 影响 / 依据 / 确认后的改动落点 / 请确认
每轮最多 3 条，按影响排序；纯审美偏好不占名额

### 变更记录（v2+）
版本号、日期、采纳编号及逐条落点、未采纳项、方向契约变化
```

空的小节会省略；主体始终是“可直接粘贴的提示词”。

## 自定义

MIngC 的人格与规则都在 `cordis.patch.yml` 的 `persona.prefix` 中。修改后：

1. 保存文件；
2. 重启 DSH（或重新安装/重新启用该 bundle）让 profile 重新组合；
3. 新建任务测试。

工具组合在同一个文件的 `plugins:` 下。默认是**只读**的：`tool-fs` 关闭了 `write` 和 `edit`，也没有 shell。如果希望 MIngC 能把提示词保存成文件，可以在 `tool-fs` 配置中把 `write` 改为 `true`，并自行承担误写风险。

## 卸载

插件页 → **已安装**（标签页）→ MIngC 行 → 卸载。

> 卸载前注意：已保存的 MIngC 会话记录的是 preset id `mingc`；卸载后重启 DSH 再恢复这些会话会失败（`Unknown agent preset: mingc`），运行中的会话在本次进程内仍可用。要保留会话，请先不要卸载。

## 故障排查

| 现象 | 处理 |
|---|---|
| 安装被拒：`not-a-package` | 路径不存在、目录下没有 `package.json`，或 `package.json` 没有 `name`；确认后用绝对路径重试 |
| 安装被拒：`not-a-bundle` | `package.json` 中没有 `dsh.bundle.patch`，或它指向的 `cordis.patch.yml` 不存在 |
| 安装被拒：`already-installed` | 同一路径已经安装过；先在插件页卸载，再重新安装 |
| 命令行安装 desktop 被拒 | 必须**完全退出 DSH** 后用安装目录自带的 `dsh.cmd` 执行 `dsh plugin --profile desktop ...`；普通 `dsh --profile desktop`（启动/dump-config）永远会被拒绝 |
| 安装后预设列表没有 MIngC | 确认 bundle 已启用；重启 DSH；确认是在新建任务而不是旧会话里找 |
| 预设显示加载失败 | 打开插件页查看错误；也可看 `%USERPROFILE%\.dsh\logs\startup-*.log` 的加载诊断；修正 `cordis.patch.yml` 的 YAML/包名后重装 |
| 路径被拒绝/无反应 | 使用绝对路径；确认目录下有 `package.json`；不要加引号或多余空格；按 Host 返回的原因（`not-a-package` / `not-a-bundle`）修正 |
| 移动目录后失效 | 从新路径重新安装 |
| 从旧包名 `@local/mingc` 升级 | 先在插件页卸载旧 MIngC（或完全退出 DSH 后 `dsh plugin --profile desktop remove @local/mingc`），再安装本目录；新包名为 `MingC` |
| 想恢复默认 | 删除 bundle；内置预设不受影响 |

## 边界与隐私

- MIngC 只读：可读取工作区文件、搜索、网页检索/抓取、向用户提问；**不能**写文件、执行命令或修改项目。
- 涉及代码库事实时，它会先只读核实；无法核实时会标注“需核实”，不会编造。
- 使用 `web_search` / `web_fetch` 时，查询会发送到配置的搜索/抓取服务；不要把敏感信息放进检索词。
- 它不会把“建议”写成“已经改了”；所有改动都必须由你或编码 agent 执行。

## 开发与验证

MIngC 没有构建步骤：bundle 只由 `cordis.patch.yml` 的配置层组成，`index.js` 是空模块。

修改 `cordis.patch.yml` 后：

1. 保存文件；
2. 重启 DSH，或在插件页关闭再开启 MIngC，让 profile 重新组合；
3. **新建任务**验证（旧会话不会换新 persona）。

不启动 GUI 的验证方式（隔离 profile，不影响真实 profile）：

```powershell
# 1) 创建一个临时 profile 并安装本目录
dsh --profile mingc-check --from-default-profile web --help
dsh plugin --profile mingc-check add 'D:\MIngC'

# 2) 检查组合结果里出现 preset-mingc 与 MIngC persona
dsh --profile mingc-check --dump-config | Select-String 'preset-mingc','你是 MIngC'
```

> 没有 `dsh` 命令时，用 DSH 安装目录下的 `resources\runtime\cli\bin\dsh.cmd`。desktop profile 由桌面应用独占，不能用 `dsh --profile desktop`。
